- 现象：训练跑到 epoch 55→56（close_mosaic 生效，重建 dataloader）时，日志停止更新，主进程 PID 137 仍存活但 CPU 接近 0%，不报错、不退出
- 根因：
  - 640 分辨率下，张量是 320 的 4 倍，单 worker 内存需求从 ~1GB 涨到 ~3-4GB
  - workers=4 → Windows spawn 4 个子进程，每个都要重新 import torch、加载 CUDA DLL（cufft64_11.dll 等）
  - RAM + 页面文件被榨干（剩 1.6GB），子进程加载 DLL 失败
  - 子进程崩在 import 阶段，管道还没建立，主进程收不到通知
  - 主进程无限等 dataloader 队列 → 死锁
- 类比：类似 RTOS 里任务A等队列、任务B崩了、没有看门狗复位，A永远等下去
- 解决方案：workers=0（不 spawn 子进程）+ 可选加大页面文件 + batch 降到 4
- 教训：Windows 下 spawn 模型的内存开销远大于 Linux fork；高分辨率训练必须评估 RAM 余量
