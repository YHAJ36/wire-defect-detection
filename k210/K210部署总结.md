## 一、任务目标

把目标检测模型完整部署进 K210 芯片，跑通「摄像头采集 → 板上推理 → LCD 显示 → 串口报警（蜂鸣器）」全链路。先后训练并部署了两个单类模型：

1. **断股**（导线断股损伤）
2. **雷击**（雷击损伤痕迹）

---

## 二、硬件限制（一切设计的前提）

| 项目 | 数值 | 后果 |
|---|---|---|
| 通用内存 | 8 MB SRAM | 标准模型放不下 |
| 可用 GC 堆 | 512 KB（实测 free ≈ 502 KB） | 模型体积硬顶约 500 KB |
| KPU 特征图上限 | 320×240 | 输入分辨率封顶 224×320（须为 32 倍数） |
| 推理速度 | **1328 ms/帧（0.75 fps）** | 只能做巡检拍照式单帧判断，不能做实时视频 |
| LCD | 纯显示屏，MaixPy 0.6.2 无触摸模块 | 交互只能靠串口 |
| 报警执行器 | 仅蜂鸣器（经 STM32），无喇叭/功放 | 语音报警不可行 |

**关键实测**：标准 YOLOv5n（1.94 MB）三种加载方式（SD 卡 / /flash / kfpkg 烧写 0x800000）全部 OOM。最终模型压到 **489 KB（板上 500,008 B）** 才稳定运行。

---

## 三、为塞进 500 KB 做的结构改造

| 原结构 | 改法 | 原因 |
|---|---|---|
| width 0.25（标准 v5n） | **width 0.125**（44.4 万参数） | 体积压到 489 KB |
| SiLU 激活 | **ReLU** | nncase 0.2 只支持 41 个 ONNX 算子，SiLU 拆出的算子不支持 |
| SPPF（串行 MaxPool） | **SPPFK**（复制 3 份 concat） | MaxPool 导入直接段错误（exit 139） |
| 动态 Upsample | **Up2**（固定 scale） | 动态上采样带进 Shape/Cast/Slice/Unsqueeze 等 4 个不支持算子 |

两个影响结果的训练设置：

- **必须关闭 AMP**：fp16 下小目标 CIoU 损失的 `torch.atan` 溢出 → 直接训出 NaN。
- **用官方 v5n 权重按通道切半初始化**：44 万参数下收敛快一倍；分段训练会因 lr 已衰减完而假收敛（150 轮收尾只有 12.9%，热启动 250 轮后 25.2%）。
- 自定义类（SPPFK/Up2）**必须放 `yolov5/models/common.py`**，否则 best.pt 记成 `__main__.SPPFK` 无法反序列化。

## 四、结果

### 跨段泛化测试（test 段与训练段不重叠，不同线路不同光照）

| 模型 | 轮数 | mAP@0.5 | 召回率 | 精确率 |
|---|---|---|---|---|
| 断股 | 400 | **25.2%** | 22.2% | 48.0% |
| 雷击 | 300 | **61.0%** | 53.0% | 81.5% |

同数据集验证集 mAP 92.8% → 跨段 61.0%，差距是真实域偏移（相机/光照/塔型不同），61% 是未见场景下的真实水平。**雷击模型达到板上可用标准。**

### 板上量化损失

板端最高 logit -2.32 vs PC 端 fp32 -2.54，差异小于量化噪声，int8 量化未伤模型。

---

## 五、阈值标定（关键教训）

沿用断股模型阈值 -2.2 时，雷击模型对桌面背景 **20 帧误报 17 次**。

板上实测（拿 test 集雷击图回传）得到清晰分界：

- 真实雷击：logit **-0.00 ~ 1.22**（置信度 0.50~0.77）
- 背景误报：最高 **-0.73**（置信度 0.33）

阈值取中间偏保守的 **-0.5**，复测 20 帧背景误报 **0 次**。

注意：这一步只能板上实测，不能靠 PC 扫 `--conf-thres` —— yolov5 报的 P/R 是最优阈值下的值，不随参数变；且板上是 uint8 量化，数值分布与 fp32 本来就有偏移。

## 六、部署链路与报警

```
训练(train_k210.py) → 导出 ONNX(export_k210_trained.py)
→ ncc 编译 kmodel(compile_demo.bat) → 串口上传(upload_kmodel.py, 带字节校验)
→ 板上运行(run_demo.py: LCD + 框 + obj值) → UART1(IO30, 9600) 发 {fail}
→ STM32 → 蜂鸣器（3 秒冷却）
```

实测 20 帧触发 5 次，报警链路正常。板上稳定 **1328 ms/帧**。

### 部署过程踩过的坑（复现时必看）

- **nncase 0.2 不支持的算子**会报 `Shapes must be same, but got [] and [...]`（LeakyRelu 标量展开）或直接段错误（MaxPool）。
- **Git Bash 会把 `/flash/xxx` 改写成 Windows 路径**，串口上传全部丢失 → 加 `MSYS_NO_PATHCONV=1`。
- **MaixPy FAT 驱动**写 1.9 MB 到 90% 丢目录项 → 一次连写 8 块 + 断点续传。
- **mpremote** 与 MaixPy 0.6.2 握手不兼容（`could not enter raw repl`）→ 用自写 upload_kmodel.py。
- **软复位清不掉 AI 缓冲**，需 `machine.reset()`；逐层 `del o` + `gc.collect()` 防 OOM。
- Type-C 座单向，只能按正确方向插。

---

## 七、明确的边界（答辩口径）

- **能做**：巡检拍照式损伤识别 —— 单帧定案，0.75 fps 完全够用。
- **不能做**：实时视频流监测 —— 闪电毫秒级事件，1.3 秒一帧会整个漏掉；这是任务性质 + 芯片代差，不是模型问题。
- **升级路径**：换 K230（128 MB、6 TOPS）可跑 640×640 实时，但 kmodel v3 导出链路要重走一遍。

**一句话结论**：K210 在 8 MB 内存卡到 500 KB 模型的前提下，雷击模型跨段 61.0% mAP、板上误报清零、报警链路全通。性能天花板来自硬件，不是算法。

## 十、复现最小命令集

```bash
# 1. 单类数据集派生（以雷击为例）
python v5/build_cls_ds.py --cls strike --name strike

# 2. 训练（width 0.125 / 320 / 关AMP，结构已内置）
python v5/train_k210.py --data v5/dataset_strike/data.yaml --epochs 300

# 3. 跨段评估
python v5/eval_k210.py --data v5/dataset_strike/data.yaml --weights <best.pt>

# 4. 导出 + 编译（自定义类在 common.py，直接可导）
python v5/export_k210_trained.py --weights <best.pt> --out strike.onnx
compile_demo.bat   # ncc → strike.kmodel

# 5. 串口上传（板子接 COM9）
python v5/upload_kmodel.py --file strike.kmodel --dst /sd/strike.kmodel

# 6. 板上运行
python v5/run_demo.py --model /sd/strike.kmodel --frames 600 --timeout 900
```
